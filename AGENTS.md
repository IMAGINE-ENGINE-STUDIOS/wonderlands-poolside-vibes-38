
- SOCIALITE architecture rules live in src/components/socialite/AGENTS.md — why: keeps root small.
- Every home discipline links to a suite (src/lib/suiteRoutes.ts); non-dedicated ones use /suites/:category (CategorySuite on ProductSuite); every suite lists all boards; FlipEditorBoard opens SurveyQuoteTool — why: one board+quote path for all trades.
- Command Center and Contractor/Supplier hubs share `/admin` (AdminDashboard picks the workspace by role) and show only database-derived figures; never add sample rows or invented stats — why: one protected entry point, trustworthy numbers.

- Multi-tenancy: business tables carry company_id (default current_company_id(), platform company for public visitors); RLS grants company members via is_company_member(); company roles live in company_members, never profiles — why: licensed companies must never see each other's data.
- One sign-in: all users use /auth; business sign-up (account_type=business) creates a company + owner in handle_new_user; legacy login routes redirect — why: one secure gateway.
- Three dashboards, one shared shell (`components/shell/EditorialShell`): `/admin` Command Center (main_admin only; businesses are redirected), `/workspace` CompanyWorkspace (company from company_members), `/account` CustomerAccount; `/admin/preview/:view` renders the latter two read-only for admins — why: separate solutions, one look, testable without the end user.
- `/dev/command-center` (DevStaging, dev builds only) renders the Command Center (AdminDashboard previewMode), company workspace and customer account without sign-in; data stays RLS-protected — why: designs can be checked without a real account. Command Center sections use white panels and black text classes directly, not dark overrides.
- CRM lives in crm_accounts/crm_contacts/crm_deals/crm_activities and web-builder pages in company_sites, all company_id-scoped via is_company_member(); quotes/invoices link to deals via nullable deal_id — why: one CRM per licensed company, no second CRM.
- /auth shows four portal choices (Company, Customer, Admin, Sales team) but the account's role decides the destination (destinationFor in AuthPage); the investor demo account opens /demo/command-center (AdminDashboard previewMode, no company data) — why: one login, no investor access to real data. Site lead emails go through site-lead-notify, which looks up the recipient server-side — why: visitors can't choose who gets emailed.
- Quote titles, inclusions and warranties per category live in src/lib/quoteDisciplines.ts; solar quote lines are suggested by src/lib/solar/solarQuote.ts from solarHardware rates and stay editable — why: one quote format for every product, no invented figures.
- 2D→3D pool outlines are sampled once by densifyPoolOutline (curveUtils) in SceneConverter, keeping the 2D control points in scene.pool.sourcePoints; generateCurvedPoolPoints passes dense outlines through untouched — why: 3D curves match the 2D canvas exactly and every 3D part shares one outline.
- Landscaping Studio (`components/landscape/LandscapeStudio`) stores its plan in the shared FLIP board `landscaping__global-design`; looks/Genius edits go through `lib/landscape/landscapeOps.ts` and Genius uses the Groq `landscape-genius` function — why: one plan feeds the board, the section estimate and the global design board.
- Genius language layer = src/lib/genius/geniusLanguage.ts (detectLanguage, translateTexts via Groq genius-translate, pickVoice native voices); intent parsing = geniusKnowledge.answerIntent (English-normalised) — why: one multilingual path for every search box and the narrator.
- Board pools/spas (lib/design/board3D.ts): first = primaryId/primaryPts/primaryFinish, extras = Water3D keyed by item id with own depth/finishes and lawn cut; applyBoard3DToItems writes 3D edits back; drawn on the board itself with catalog finish photos — why: independent water bodies, two-way sync, one board.
- Subdirectories have their own AGENTS.md (e.g. components/socialite, components/designStudio, components/siteBuilder); read it before changing files there.
- Website builder and public company sites rules live in src/components/siteBuilder/AGENTS.md — why: keeps root small.
- Showroom page-scale tools launch explicitly, one at a time, inside contained widgets; global/2D/3D frames use embedded DesignStudio with an initial view and SiteBuilder uses embedded mode — why: prevents fullscreen escapes, competing board listeners and idle 3D workloads.
- AuthProvider shows its blocking loader only for the first session check; later sign-ins (e.g. showroom demo session) never unmount the app — why: open tools kept losing state and looked unclickable. /website-builder is a standalone page that renders the same SiteBuilder component — why: one builder version everywhere.
